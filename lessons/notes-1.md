# Находки по общему движку · смена 1 · devops-aws-vpc

Движок (`assets/`, `tools/`, `check.sh`) этот сайт не правит (§1 AGENTS.md). Ниже - апстрим-репорты для ростка `seed/swa/`.

## 1. Дымовой тест поиска зашит на `ru/02.html`, а росток велит брать слово из темы 01

- **Что.** `tools/check-pages.mjs` проверяет поиск на одной жёстко названной странице - `02.html` - и требует, чтобы среди результатов был раздел **этой же** страницы. При этом `BRIEF.md` §4 и комментарий в `site.conf`, оба приехавшие из ростка, велят взять словом поиска «термин из той страницы, которая написана первой», подразумевая `ru/01.html`. Сайт, который сдаёт Батч 1 по модели §5.15 AGENTS.md, пишет витрину и темы 01-05 и честно берёт слово из главы 01 - и получает КРАСНОЕ, если этого термина нет в тексте главы 02. Расхождение не в коде, а между кодом проверки и инструкцией ростка.
- **Чем доказано.** При `search = CIDR` и написанных страницах `ru/index.html`, `ru/01.html` - `ru/05.html` полный `./check.sh` ответил `КРАСНОЕ`, девять ДА из десяти, с единственной строкой брака: `ru/02.html: среди результатов нет раздела текущей страницы 02.html`. Источник требования - `tools/check-pages.mjs`, строки 193-194: `const samePage = links.find((a) => (a.getAttribute('href') || '').startsWith('02.html#')); if (!samePage) return ['среди результатов нет раздела текущей страницы 02.html'];`
- **Как обойдено на сайте.** Термин `CIDR` введён в текст `ru/02.html` в двух естественных для главы местах: длина префикса подсети в разделе о планировке и неизменность блока в разделе о запретах. Текст от этого не пострадал - глава действительно про блоки подсетей, - после чего `node tools/check-pages.mjs` ответил `страниц проверено: 73, в браке: 0`. Ни один файл в `tools/` и `assets/` не правился.
- **Что предлагается для ростка.** Самая дешёвая правка - документационная: в `BRIEF.md` и в комментарии к строке `search` в `site.conf` сказать прямо, что слово поиска обязано находиться на `ru/02.html`, потому что именно её берёт дымовой тест. Правка в коде лучше: выбирать страницу дымового теста не константой, а первой русской страницей, попавшей в индекс поиска, либо требовать «хотя бы один результат с якорем» вместо «раздел текущей страницы», когда проверяемая страница сама ещё скелет. Константа `02.html` безобидна на сайте, сданном целиком, и вредна ровно в батчевой модели поставки, где написанные страницы появляются волнами.

## 2. Браузерная проверка плавает: фиксированный бюджет 3 секунды на открытие панели поиска

- **Что.** `tools/check-pages.mjs` ждёт появления `.search-input` после клика по кнопке поиска не дольше 60 попыток по 50 мс, то есть ровно 3 секунды, и при превышении возвращает брак «панель поиска не открылась». Бюджет фиксированный и не зависит ни от размера индекса поиска, ни от загруженности машины. Внутри `./check.sh` браузерная проверка стоит десятой по счёту, то есть в самом нагруженном месте прогона, и именно там он иногда не выдерживается. Отказ неотличим от настоящего дефекта вёрстки: строка брака одна и та же.
- **Чем доказано.** В одной и той же рабочей копии, без единой правки файлов между прогонами: полный `./check.sh` ответил `КРАСНОЕ`, девять ДА из десяти, со строкой `ru/02.html: панель поиска не открылась`; три последовательных изолированных прогона `node tools/check-pages.mjs` сразу после этого ответили `страниц проверено: 73, в браке: 0`, трижды `ЗЕЛЁНОЕ`; повторный полный `./check.sh` ответил `ЗЕЛЁНОЕ`, десять ДА из десяти. Индекс поиска на этот момент - `ru: 56 записей, 91 КБ`.
- **Как обойдено на сайте.** Никак: обойти нечем, правка лежит в `tools/`. Прогон повторён, и в запись смены вынесен тот вывод, который воспроизводится - десять ДА из десяти. Факт плавающего отказа зафиксирован здесь честно, чтобы следующая смена не искала дефект вёрстки там, где его нет.
- **Что предлагается для ростка.** Поднять бюджет ожидания с 3 секунд до 10 и сделать его параметром, а не константой: клик по кнопке поиска тянет за собой разбор индекса, и 91 КБ на этом сайте - далеко не предел, банки по 50 вопросов и словарь увеличат его в несколько раз. Отдельно стоит развести два сообщения: «панель не открылась за N секунд» и «панели нет в разметке» - сейчас оба читаются как дефект страницы, хотя первое обычно дефект бюджета.

## 3. Проверка телефона не видит перенос внутри блока кода, и предел в знаках нигде не записан

- **Что.** `assets/style.css` ставит на `pre code` правила `white-space: pre-wrap` и `overflow-wrap: anywhere` - сознательно, чтобы длинная команда не выезжала за край телефона. Побочное следствие: выехать за край блок кода больше не может **никогда**, поэтому `node tools/check-pages.mjs`, который ищет именно выезд за край, на блоках кода слеп по построению. Строка, не влезшая в ширину, молча переносится, и всякое выравнивание по столбцам - таблица маршрутов, набор правил, нарезка адресов - рассыпается, а проверка отвечает `в браке: 0`. Для команды это правильное поведение, для схемы и таблицы - тихий дефект вёрстки, который видит только глаз.
- **Чем доказано.** Измерено в браузере на `ru/03.html`, телефон 390px: ширина коробки `pre code` равна **254.28px**, ширина знака `ui-monospace` 14.08px равна **8.477px**, то есть в строку помещается ровно **30 знаков**. Кириллица меряется так же, как латиница: проба из десяти `щ`, десяти `a`, десяти `0` и десяти `·` дала одно и то же число 8.477, так что смешанные столбцы выравниваются точно. При первой верстке блоков я оценил предел в 36 знаков арифметически и ошибся: пятнадцать блоков из восемнадцати переносились, при этом `./check.sh` отвечал `ЗЕЛЁНОЕ`, десять ДА из десяти.
- **Как обойдено на сайте.** Все восемнадцать блоков перевёрстаны под измеренные 30 знаков, после чего перенос исчез. Проверялось не высотой блока - этот способ дал систематическую ошибку в одну строку на всех блоках сразу, - а прямо: временно выключить `white-space` в `pre`, сравнить `scrollWidth` с `clientWidth`, вернуть обратно. Разница и есть то, что было бы перенесено. Скрипт держался вне репозитория, `tools/` и `assets/` не правились.
- **Что предлагается для ростка.** Добавить в `tools/check-pages.mjs` отдельный пункт для `pre code` по этому способу: на каждой странице снять `white-space`, замерить переполнение, вернуть - проверка дешёвая, страница уже открыта в браузере. И записать измеренное число в `AGENTS.md` рядом с правилом о запрете многоколоночных таблиц (§5.12, §5.16): **в блоке кода на телефоне 390px помещается 30 знаков в строке**. Сейчас это число не записано нигде, и каждый следующий сайт серии будет выводить его заново через испорченную поставку. Ограничение особенно важно для глав 10-12, где по §5.12 код показывают в `pre` обязательно.
